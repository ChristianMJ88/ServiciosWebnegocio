### API desde un dominio propio

La configuración pública y el resolver de API usan `/api/v1` en hosts publicados; clientes enruta `/api/**` por apiProxy, sin una API elegida por el tenant. Sin embargo, el proxy conserva Origin en POST y el CORS estático del backend rechazaba un dominio nuevo. Se añade permiso CORS dinámico **solo para las rutas públicas y registro de cliente**, consultando en backend el dominio activo y su capacidad vigente. No abre CORS de administración, plataforma ni acceso interno a los dominios de tenants. Se conserva la lista de orígenes de plataforma existente y no se elimina Origin del proxy. Prueba de configuración/POST en comprobación.

El login social continúa en el origen de la app mediante la redirección existente; no se cambia su configuración. Las restricciones reales del proveedor de pagos y de dominios autorizados externos siguen siendo comprobaciones obligatorias antes de conectar un dominio real, no se configuran en esta entrega local.
